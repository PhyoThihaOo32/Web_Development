Different Between Git and GitHub

Git is a distributed version control system that tracks changes in source code and allows developers to manage different versions of a project.

GitHub is a cloud-based platform that hosts Git repositories and provides collaboration features such as pull requests, code reviews, issue tracking, and project management. In short, Git manages the code history, while GitHub provides a place to store and collaborate on Git repositories. .

Git Daily Loop: edit, stage, commit, push

  • EditMake changes to the code files.
  • StageAdd the changed files using git add .
  • CommitSave a snap shot using git push

Git commands

  • git initCreates a new git repository.
  • git status Show the current state of the working directory.
  • git add . Stages all changed files for the next commit.
  • git commit -m "message Saves a snapshot of your staged changes.
  • git pushUploads your commits to GitHub.
  • git pullDownloads and merges the latest changes from GitHub.
  • git cloneCopies a remote repository to your computer.
  • git logDisplays the history of commits in the repository.

Git Command Reference

In Git and GitHub, a ref (short for reference) is a user-friendly pointer or nickname for a specific commit hash. Instead of memorizing a long SHA-1 string like 1a410e..., you use named refs such as branches or tags to navigate your repository's history.

Things I should not commit

Some files should never be pushed to GitHub because they may contain sensitive information or unnecessary data.

  • .env :Stores environment variables and API keys.
  • Secretes :Passwords, tokens, private keys, and credentials should always stay private.
  • node_modules :Contains installed packages and can be recreated with npm install.
  • .DS_Store :A macOS system file that is not needed for the project.
  • Build Outputs: Exclude compiled code, executable files (.exe, .dll), and dist folders.
